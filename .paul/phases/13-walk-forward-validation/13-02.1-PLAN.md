## D1 — the exact metric (as originally posed)
Item 1 can be read three ways. They behave differently:

| | formula | inverts on a losing window? | sees carry cost? |
|---|---|---|---|
| (a) pure drawdown ratio | `MDD / MDD_spy` (lower better) | no | **no** — ignores return entirely, so calm windows pick whatever shaves the most drawdown regardless of the premium it burned. That would discard 13-02's main finding, that calm-period carry decides the answer |
| (b) return over relative drawdown | `R / (MDD / MDD_spy)` | **yes** — still negative return over a denominator, same defect as now | yes |
| (c) **relative wealth over relative drawdown (recommended)** | `[(1+R)/(1+R_spy)] / [MDD/MDD_spy]` (higher better; 1.0 = SPY) | no — both factors are positive, and the score rises in return and falls in drawdown, monotone in each | yes |

(c) has no sign trap, keeps the carry trade-off, and puts every window on one scale centred on SPY = 1.0.
That makes Grid B's relative view the score itself and removes the need for per-column colour
normalisation. (a) and the old floored Calmar are kept as DESCRIPTIVE columns. The drawdown floor stays,
applied to both drawdowns, so a near-zero MDD_spy cannot blow up the ratio.

## D2 — the premium budget (default proposed, confirm)
`budget_moneyness = 1.00`, i.e. the ATM put, per item 2. Measured earlier: an ATM 63-day put is about
3.5% of spot, so every configuration spends about **14% of notional a year** on premium. Every strike pays
the same, so carry drag no longer differs by strike, only by what the contracts return. A
`budget_moneyness` parameter is exposed so a cheaper budget (e.g. the 0.95× premium) is a one-argument
rerun, not a code change. Recommended: run 1.00 as asked, report the annual spend beside every result.

## AC-6: The fitting is built up in layers, with formulas, before the pooled surface
Given the trigger fixed at 10%
When the "fitted response surface" section renders
Then, in order:
1. A scatter with one point per (strike, window), coloured by window, on the D1 metric.
2. Fit layer (i): a global quadratic in moneyness, with its formula.
3. Fit layer (ii): a cubic regression spline with its knots drawn as vertical lines, plus the
   truncated-power / B-spline formula.
4. Fit layer (iii): the penalised B-spline actually used (`surface.fit_1d`), with its formula:
   minimise `‖y − Bα‖² + λ‖D₂α‖²`. Knots are equally spaced, not at every data point (a P-spline,
   not a classical smoothing spline; the difference is stated). The knots are drawn, and λ is chosen
   by GCV, whose formula is also shown.
5. The 2-D tensor-product form, `f(m,d) = Σᵢⱼ αᵢⱼ Bᵢ(m) Bⱼ(d)` with penalty
   `λ_m‖(I⊗D₂)α‖² + λ_d‖(D₂⊗I)α‖²`.

Only then come the per-window surfaces, the pooled surface and snapping. Every formula is typeset
with the page's existing `.math` CSS (no CDN).
