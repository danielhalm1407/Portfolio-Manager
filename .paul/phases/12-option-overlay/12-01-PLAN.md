<objective>
## Goal

Three hedge structures from the Obsidian catalogue — protective put, put spread, rolling collar —
expressed as executable rules that slot into the existing `RebalanceRule.propose` contract, so
the Phase 2 simulator accounts them unchanged.

## Goal, stated as a number

Given a synthetic vol surface derived from the Phase 11 history, the rolling collar on SPX must
price correctly for at least three historical 63-day windows covering different regimes. If it
does not, this plan has not succeeded, regardless of how much scaffolding was written.

## Purpose

Phase 12 is the second phase of milestone v0.4. Phase 11 established that the hedge structures
can be priced — it recorded the provenance of the vol data and answered whether an implied surface
is obtainable or whether realised/VIX vol must be synthesised. Phase 12 takes that answer and
builds the pricing engine and roll mechanics. Without this, Phase 13 cannot run a walk-forward
sweep that includes any option leg; the v0.4 claim is not testable with a collar in it.

The mechanism under test in v0.4 is: a hedge leg that rallies into an equity drawdown is SOLD
into that rally by the rebalance, generating cash redeployed into the fallen growth leg near the
trough. A collar caps the upside of that rally but also limits the downside cost. Phase 13 will
ask whether the net improvement in risk-adjusted returns justifies the theta drag; Phase 12
makes that question answerable.

## Output

A new `portutils.portfolio.options` module containing `OptionLeg`, `OptionOverlayRule` (base),
and three concrete rules: `ProtectivePutRule`, `PutSpreadRule`, `RollingCollarRule`. Each plugs
into `RebalanceRule.propose` so `PortfolioSimulator` accounts them unchanged. Tests run
offline against fixtures. `COVERAGE.md` updated with a vol-provenance note.
</objective>

## AC-1: OptionLeg is a first-class pricing primitive
```gherkin
Given a strike, expiry, right (put/call), underlying spot and a vol input
When OptionLeg.price() is called
Then it returns a mark-to-model premium using Black-76 / Black-Scholes as appropriate
And the premium is always non-negative and bounded by the intrinsic value floor
```

## AC-2: Roll calendar fires on schedule
```gherkin
Given a RollingCollarRule initialised with a 63-day reset and a history panel
When the simulator advances through a 63-day window
Then the rule rolls: closes the expiring legs, strikes the replacement legs to the period-start spot,
     and records the debit or credit in the order ledger as a separate Fill per leg
And the next roll fires 63 calendar days later regardless of intervening rebalances
```

## AC-3: All three structures plug into the existing propose() contract
```gherkin
Given PortfolioSimulator configured with a ProtectivePutRule, PutSpreadRule or RollingCollarRule
When simulator.run() is called
Then propose() returns {symbol: units} for option legs alongside equity legs
And the Fill accounting for option premium flows through the existing fills.py primitives unchanged
And the realised P&L from a closed option leg is attributed to the hedge sleeve
```

```gherkin
Given a completed simulation run that includes at least one option overlay

And premium is disaggregated per structure so collar, put, and put-spread costs are separately legible
```

    Option C (realised-vol-only): Neither an implied surface nor a VIX index is available beyond
    recent history. The engine uses a rolling realised-vol estimate (e.g., 21-day or 63-day) as the
    vol input. Pricing is approximate; every downstream result carries that caveat.

<task type="auto">
  <name>Task 1: Build OptionLeg, the roll calendar and the three rule classes</name>
  <files>src/portutils/portfolio/options.py, src/portutils/portfolio/rules.py, config/asset_universe.yaml</files>
  <action>
    Create `src/portutils/portfolio/options.py` as library code (import-safe, no side effects).
    The module must contain:

    **OptionLeg dataclass**
    - Fields: `symbol`, `right` (Literal["P","C"]), `strike`, `expiry` (date), `quantity` (signed
      int, negative = short), `open_premium` (float, per-share cost at entry)
    - `price(spot, vol, r, t) -> float`: Black-Scholes put/call price. Use scipy.stats.norm,
      already a declared transitive dependency. Return max(intrinsic, BS) so deep-ITM legs never
      go below intrinsic.
    - `delta(spot, vol, r, t) -> float`: first-order Greeks for position sizing
    - `theta_to_expiry(spot, vol, r) -> float`: total remaining time-value bleed in currency units,
      for the theta-drag report

    **RollCalendar**
    - `__init__(reset_days: int = 63)`: the 63-day reset documented in "How to roll a put hedge"
    - `next_roll(from_date: date) -> date`: `from_date + timedelta(days=reset_days)`, calendar days
    - `is_roll_day(current_date: date, entry_date: date) -> bool`
    - No market-calendar dependency — calendar days, as the Obsidian note specifies

    **OptionOverlayRule (abstract base)**
    - Subclasses `RebalanceRule` so `PortfolioSimulator` needs no changes
    - `_open_legs(spot, vol_input, as_of) -> list[OptionLeg]`: abstract, implemented per structure
    - `_close_legs(legs, spot, as_of) -> list[Fill]`: marks legs to model and returns Fills with
      `rationale` set to the structure name and reason ("roll", "expiry", "exercise")
    - `propose(book, prices, as_of) -> dict[str, float]`: checks the roll calendar; if a roll is
      due, appends close-old + open-new legs to `self.last_rationale`; returns `{}` if no equity
      rebalance is triggered — the option leg appears in the Fill ledger, not the weight target

    **ProtectivePutRule**
    - Buys one put per 100 shares of the underlying equity leg
    - Strike: `notional_pct` below spot (e.g., 0.95 = 5% OTM), configurable
    - Expiry: one roll-calendar period forward
    - Does NOT write a call — pure downside protection, maximum cost

    **PutSpreadRule**
    - Buys the put as above AND writes a put `spread_width` lower (e.g., 0.80 = second strike at
      80% of spot) to partially offset premium
    - The written leg must always have a lower strike than the bought leg — assert this, never
      silently swap
    - Net premium is long-put cost minus short-put credit; record both legs individually in the
      Fill ledger so the gross and net are separately visible

    **RollingCollarRule**
    - Buys the put as above AND writes a call `upside_cap` above spot (e.g., 1.05 = cap upside at
      +5%)
    - 63-day reset per `RollCalendar`; strikes re-struck to period-start spot, as "How to roll a
      put hedge" specifies
    - At roll: close put (buy back) + close call (buy back), then open new legs — four Fills per
      roll event, each with rationale "collar roll"

    **config/asset_universe.yaml** — add an `option_overlay` section naming the underlying for
    each structure (SPX or SPY), the default `notional_pct`, `spread_width`, `upside_cap` and
    `reset_days`. Follow the existing named-portfolio convention; do not hardcode in the rule.

    Avoid: importing IBKR or yfinance inside options.py — the module must be import-safe with no
    network dependency. Vol input is a float (or Series) passed in from the pipeline, not fetched
    inside the rule.
  </action>
