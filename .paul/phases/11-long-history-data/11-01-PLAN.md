<objective>
## Goal

A reproducible long-history price and volatility cache spanning multiple market regimes, assembled
from IBKR where it reaches and a free source where it does not, with the provenance of every series
recorded and every gap named.

## Goal, stated as a number

The 2008 drawdown, the 2020 crash and the 2022 rate shock must all be present in the cached panel for
at least the index leg. If they are not, this plan has not succeeded, regardless of how much code was
written.

## Purpose

v0.4 claims that hedge structures improved risk-adjusted returns across many historical points and
regimes, and that parameters fitted on a backward window kept working on the forward window that
followed. Every cached panel today is **250 rows spanning 2025-07-28 to 2026-07-24** — one year, one
regime. On that data the claim is not weakly supported; it is untestable. Phases 12 to 15 are all
blocked behind this one.

This also settles a question Phase 12 cannot proceed without: whether a genuine option-implied
volatility surface is obtainable at all, or whether the option overlay must synthesise prices from
realised or VIX-implied vol. That answer must come from evidence, not assumption — consistent with
the standing project decision that on IB questions the running TWS outranks every written source.

## Output

A `portutils.ingestion.history` module, an extended `cache_prices.py`, long-history parquets under
`data/processed/`, a `COVERAGE.md` naming every gap and source, and tests that run offline.
</objective>

## AC-1: History reaches past the per-request ceiling
```gherkin
Given a symbol and a requested span longer than one IBKR request will serve
When the long-history fetcher runs
Then it issues multiple paginated requests, stitches them into one continuous series,
     and the result contains no duplicated and no silently dropped bars
And the stitch seams are verified by comparing overlapping bars between adjacent requests
```

## AC-2: Free sources fill what IBKR will not serve
```gherkin
Given a symbol whose IBKR history stops short of the requested start date
When the fetcher exhausts the IBKR path
Then it falls back to the free source for the unreachable span
And every row records which source produced it, so no series silently mixes provenance
```

## AC-3: Coverage is stated, not assumed
```gherkin
Given a completed long-history build
When the coverage report is generated
Then it names, per symbol: first and last bar, row count, source or sources, and every internal gap
And it states explicitly whether the 2008, 2020 and 2022 episodes are covered
```

## AC-4: Existing callers keep working
```gherkin
Given the existing one-year panels and the code that reads them
When the new ingestion path is added
Then research/rebalance_realisation.py and src/pipelines/rebalance_study.py run unchanged
And the existing parquet files are not overwritten or reformatted
```

## AC-5: The volatility-surface question is answered with evidence
```gherkin
Given the need for option pricing in Phase 12
When the vol-data probe runs
Then it records what was actually obtainable — implied surface, VIX-style index level, or realised
     vol only — with the probe output as evidence
And Phase 12's pricing approach is thereby determined rather than assumed
```

## AC-6: Ragged history survives caching, loading, rebasing and plotting
```gherkin
Given symbols whose listing histories start years apart (e.g. SPY 1993 beside QQQ 1999)
When cache_prices.py writes a NEW long-history tag
Then the parquet retains every bar back to the EARLIEST series' first observation
And no symbol's history is truncated to the latest first-bar across the universe
And COVERAGE.md's reported span for each symbol matches what the parquet actually holds

Given an EXISTING tag (spy_kmlm, hedge_rotation, holdings)
When cache_prices.py is re-run for it
Then the output is byte-identical to the parquet already on disk

Given price series whose coverage windows do not fully overlap
When PanelBuilder loads them with the default settings
Then behaviour is byte-identical to today — outer join, ffill, dropna — and every existing
     caller and figure is unchanged

When PanelBuilder loads them with the ragged mode enabled
Then no row is dropped for want of a value in another series
And each series is NaN outside its own coverage, which Plotly renders as a gap in the line
And no `print` or silent truncation hides the fact that coverage differs per series

Given a ragged frame and the "common" anchor policy
When it is rebased to a wealth index
Then every series equals exactly the base value on the first date where ALL series have data
And a series whose history starts earlier is shown above or below the base before that date
And no series is emptied to all-NaN by dividing through a NaN anchor

Given a ragged frame in which no single date has every series populated
When the "common" anchor policy is requested
Then a clear error names the series that fail to overlap, rather than raising IndexError
```

    **Step 0 — the cache layer, which runs FIRST and has the same defect.**
    Added 2026-08-31 after the Phase 11 survey (see CONTEXT.md §3). `_tidy`
    (`src/pipelines/cache_prices.py:45`) ends at `:55` with
    `out.astype(float).ffill().dropna(how="any")` — the identical outer-join-then-dropna
    truncation as `PanelBuilder._load`, one layer EARLIER. A SPY-from-1993 series cached
    beside a QQQ-from-1999 series is truncated to 1999 **in the parquet itself**, before
    `PanelBuilder` is ever constructed and before COVERAGE.md is generated. Fixing only the
    viz loader would bake the data loss into the very file COVERAGE.md describes, so AC-3
    and AC-6 fail together.

    The compatibility argument differs from Step 1 and the difference matters. `panel.py` is
    read by existing figures, so an opt-in mode is required there. `cache_prices.py` WRITES
    NEW FILES UNDER NEW TAGS — a long-history tag has no existing reader to regress, and the
    three existing parquets are protected by this plan's DO-NOT-CHANGE list regardless. So
    ragged retention may be the behaviour for new panels rather than an opt-in, provided
    re-running an existing tag still reproduces its current bytes.

    Retain `_tidy`'s existing comment verbatim — "Forward-fill isolated gaps ... but drop any
    leading rows still missing a quote — the sim must never mark a leg at a made-up price".
    That rationale is CORRECT for a simulator frame and WRONG for a coverage frame; both
    needs are real and they are not the same frame. Add the ragged reasoning alongside it,
    do not rewrite it.

    Without this task the plan can cache 1990 and still show 2006 in every figure. `_load`
    (`viz/panel.py:165-167`) ends with an outer join, then `ffill`, then `dropna`, which
    truncates the WHOLE panel to the latest first-bar across all tickers. The only `print` in
    `_load` fires on a load exception, never on truncation, so `COVERAGE.md` would claim a span
    that no plot can show. Fix the loader and the rebase together — separately, each still fails.

    **Step 1 — opt-in ragged loading in `PanelBuilder._load`** (the second of the two sites).
    Keep the existing `ffill` + `dropna` as the DEFAULT so that no current caller, notebook or
    figure changes behaviour; this is the 2026-08-31 decision in STATE.md and it is what makes
    the change non-regressive. Add an opt-in mode (constructor argument, defaulting to today's
    behaviour) that retains rows where only some series have data. In that mode each series stays
    NaN outside its own coverage; Plotly renders NaN as a break in the line (`connectgaps`
    defaults to False), which is the correct reading of "this instrument did not exist yet".
    Whichever mode is active, report per-series first and last bar so a truncation is never
    silent — the current code's failure was silence, not the `dropna` itself.

    Comment retention: the existing block comment above these three lines explains ffill as the
    non-trading-day convention. It stays, verbatim, on the default branch. Add the ragged branch's
    reasoning alongside it, do not rewrite the original.

    **Step 2 — an anchor policy on the rebase, in `analysis/returns.py`.**
    `normalise` (`returns.py:203`) and `pct_returns` (`:210`) both divide by `df.iloc[0]`. On a
    ragged frame any series that is NaN on row 0 divides through NaN and the ENTIRE column becomes
    NaN — an invisible trace, with no error raised. Add an `anchor` parameter to both, defaulting
    to the current `iloc[0]` behaviour:

      - `"first_row"` (DEFAULT) — today's `df.iloc[0]`. Unchanged, so existing callers are safe.
      - `"common"` — anchor at the first date where EVERY series has data:
            anchor = df.dropna().index[0]
            out = (df / df.loc[anchor]) * base
        Every series equals `base` on that date, so the series are directly comparable. A series
        whose history starts earlier keeps that history, shown above or below `base` — that is
        meaningful information about where it stood relative to the common baseline, not an
        artefact to be trimmed.
      - `"self"` — each series anchored on its own first valid observation
        (`df[col].first_valid_index()`). Right for "growth of 100 since inception" per series, but
        the resulting levels are NOT comparable across series; say so in the docstring so nobody
        reaches for it expecting a comparison chart.
      - an explicit `pd.Timestamp` — anchor there. This exists because one late-starting series
        drags `"common"` forward and can discard the comparability of everything before it: a vol
        series starting 2005 beside SPX from 1990 makes the common anchor 2005.

    `"common"` must raise a clear error naming the non-overlapping series when `df.dropna()` is
    empty, rather than letting `.index[0]` raise a bare IndexError.

    `daily_returns` and `log_returns` need NO anchor: `pct_change()` is per-series and already
    correct on ragged input, yielding only leading NaNs. Leave them alone and note why.

    **Step 3 — thread the policy through the two plotting utilities.**
    `PanelBuilder._normalise` / `_pct_returns` (`panel.py:187-199`) are wrappers over
    `analysis.returns`; pass the anchor through, keeping the default. In `dash_timeseries_app`,
    `_build_level_figure` (`:680`) has the identical defect — `first_value = series.iloc[0]`, so a
    series starting NaN renders as an all-NaN, invisible trace under `cfg.reindex=True`. Make
    `reindex` accept the same policy values as `anchor` while continuing to accept its current
    bool (`True` -> `"first_row"`, `False` -> raw levels), so no existing `TimeSeriesAppConfig`
    changes meaning.

    Note for whoever implements this: `_validate_inputs` (`dash_timeseries_app.py:603`) already
    accepts ragged input — it never calls `dropna` — and every `PanelBuilder` plotting method
    already takes `df=None` defaulting to `self.df_all`, so a ragged frame can be passed in
    directly today. The plot layer never required the `dropna`. Only `_load` and the rebase do.
  </action>
