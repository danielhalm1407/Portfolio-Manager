<objective>
## Goal
Publish ONE static HTML page that reads as a piece of analysis: the
`research/option_overlay_probe.md` write-up, in order, with each figure embedded at the finding it
belongs to. Served from `docs/` by GitHub Pages, no server, no build step, sharing the
`plotly.min.js` already vendored there.

## Purpose
This is Phase 10 Track A's actual deliverable. `docs/` today holds five standalone figure pages and
a link list — a reader lands on a chart with no argument around it. The findings, the caveats and
the scoped-but-unbuilt next steps already exist in the write-up; they are simply not published.
This is also the project's first public piece of analysis, so it is what a reader is pointed at.

## Output
- `src/pipelines/build_report.py` — Markdown + figures → one themed HTML page
- `docs/index.html` becomes the report; the existing per-figure pages stay (the write-up links to them)
- `docs/README.md` documents the regeneration command
</objective>

<task type="checkpoint:decision" gate="blocking">
  <decision>How Markdown becomes HTML, given the repo declares no Markdown dependency</decision>
  <context>
    The write-up uses headings, tables, bold/italic, inline code, fenced code, links and blockquotes.
    Tables are the hard part — they rule out a naive regex converter.

    `markdown_it` (markdown-it-py 4.0.0) is present in venv-stats but is NOT in pyproject.toml's
    dependencies; it arrives transitively. pricing.py records the standing objection to relying on a
    transitive package (that is exactly why the pricer uses math.erf rather than scipy).
  </context>
  <options>
    <option id="declare-markdown-it">
      <name>Declare markdown-it-py in pyproject.toml and use it (RECOMMENDED)</name>
      <pros>CommonMark-correct including tables; already installed so nothing to install; pure Python, no C extension; one line in pyproject makes the existing implicit use explicit</pros>
      <cons>A new declared dependency for a repo that has kept them few</cons>
    </option>
    <option id="hand-rolled">
      <name>Write a ~120-line converter in build_report.py</name>
      <pros>Zero dependencies, fully in-repo, no version drift</pros>
      <cons>Tables, nested emphasis and escaping are where hand-rolled converters break; it becomes a maintenance surface that has nothing to do with this project's subject</cons>
    </option>
  </options>
  <resume-signal>Select: declare-markdown-it or hand-rolled</resume-signal>
</task>
